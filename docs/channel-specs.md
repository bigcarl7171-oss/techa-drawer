# 채널별 원고 규격 — 단일 출처

분량·구조 기준이 여러 문서·스크립트에 복붙돼 있어 값이 바뀔 때마다 어긋났다
(1,200→1,800→1,500 두 번 바뀌었고, 2026-09-07 `check-publish.sh`에 옛 상수가 남아 사고).
**이제 이 표가 유일한 출처다.** 다른 문서는 숫자를 다시 적지 말고 이 파일을 가리킨다.

숫자를 강제하는 곳은 두 군데뿐이다 — `scripts/check-publish.sh`(발행 게이트)와
`scripts/publish-draft.js`(`--dry-run` 경고). 둘 다 이 파일을 읽어 값을 쓴다.
값을 바꾸려면 **이 파일만** 고치면 된다.

## 분량 하한의 근거 (왜 1,500인가)

- **구글**: 글자 수는 직접 랭킹 요소가 아니다(Yoast, Orbit Media 실측). 길이가 순위를
  만드는 게 아니라, 문제를 제대로 푸는 글이 길어지는 것이다.
- **네이버**: 공식 문서에 글자 수 기준이 없다.
- 하한의 목적은 "얇은 글 방지"뿐이고 그 목적에는 1,500이면 충분하다.
  **모자라면 문단을 늘리지 말고, 각도가 덜 채워진 것은 아닌지부터 본다.**
  (1,800을 지키려 문단을 늘리다 늘어진 사고: 2026-09-03 `autumn-flower-gift-offseason`.)
- 자세한 경위는 `docs/archive/blog-seo-history.md`.

## 네이버 해시태그 — 왜 15~25개이고, 왜 "클러스터"인가 (2026-09-19 신설)

네이버 블로그는 **검색 화면에서 테차가 들어갈 수 있는 유일한 자리**다. 자사 도메인
(techa.kr)은 네이버 통합검색에 자리가 없다 — `퇴원 축하 선물` SERP를 실측했더니 화면이
블로그 46 · 카페 25 · 지식iN · 쇼핑으로 차 있고 techa.kr은 0건이었다 (2026-09-19).

해시태그 개수보다 **무엇을 묶느냐**가 핵심이다. `serp-vertical-strategy-2026-08.md` §3에서
확인한 경쟁사 사례(`solmade4425`)는 글을 3배 많이 쓴 것이 아니라, **한 편에 관련 검색어를
전부 명시적으로 담아** `대학졸업식`·`딸졸업식`·`아들졸업식` 세 키워드에 같은 글 하나를
올렸다. 같은 소재로 4편을 따로 쓰는 것보다 커버리지가 넓다.

그래서 태그는 아무 단어나 채우는 자리가 아니라 **하나의 행사 클러스터를 펼치는 자리**다:

```
행사명        졸업식 · 졸업선물 · 졸업식선물
+ 대상        아들졸업선물 · 딸졸업선물 · 조카졸업선물
+ 학교급      중학교졸업식 · 고등학교졸업식 · 대학졸업식
+ 상품형태    졸업식꽃다발 · 비누꽃다발 · 프리저브드꽃다발
+ 브랜드      테차 · 시들지않는꽃
```

- 본문에도 그 낱말들이 실제 문장으로 등장해야 한다. **태그에만 있고 본문에 없으면
  키워드 스터핑이고, 네이버가 걸러낸다.**
- 다루지 않은 소재는 태그에 넣지 않는다 — 들어온 사람이 바로 나가면 체류시간이 깎인다.
- 클러스터가 안 잡히는 주제(브랜드 이야기·관리법 등)는 무리해서 25개를 채우지 않는다.
  그런 글은 10개 안팎이 정상이다.
