# 테차 인스타그램 카드뉴스 제작

## 목표: '좋아요'가 아니라 '저장'과 'DM 공유'

2026년 인스타그램 알고리즘은 단순 좋아요보다 **게시물이 얼마나 저장(Save)되고
지인에게 DM으로 전달되는지**에 훨씬 높은 노출 가산점을 준다.
따라서 모든 기획 판단의 기준은 하나다:

> "이 카드를 본 사람이 나중에 다시 꺼내보려고 저장하거나,
> 특정한 누군가에게 보내주고 싶어질 이유가 있는가?"

보기 좋은 이미지만으로는 부족하다. 두고두고 볼 가치가 있는
**정보 밀도 높은 실용 콘텐츠**를 카드 단위로 명확하게 쪼개서 담아야 한다.

## 작업 순서

1. **기획** — 주제·타깃·카드 구성안을 먼저 텍스트로 제안하고 사용자 승인을 받는다
2. **원고 확정** — 카드별 문구를 확정한다 (디자인 전에! 나중에 고치면 렌더를 다시 해야 한다)
3. **디자인·제작** — HTML/CSS로 카드 작성 → `scripts/render.js`로 PNG 렌더
4. **검수** — 렌더된 PNG를 Read 도구로 직접 열어 눈으로 확인 (아래 체크리스트)
5. **전달·기록** — PNG(+PDF)를 사용자에게 전달하고 진행 상황을 프로젝트 문서에 기록

1→2단계(기획·원고)에서 사용자 합의를 먼저 받는다. 합의가 되어 있으면
3~5단계는 사람 손 없이 끝까지 자동으로 진행할 수 있다 (자동화 워크플로우의 전제).

## 1. 콘텐츠 기획 원칙

**저장을 부르는 콘텐츠 유형** — 나중에 다시 꺼내볼 가치가 있는 것:

- **가이드·체크리스트**: "5060 부모님이 가장 감동하는 프리저브드 선물 BEST 3",
  "장마철 인테리어 소품 관리 4단계"처럼 구체적 노하우를 단계로 제공
- **비교표·인사이트**: 비누꽃 vs 프리저브드 소재 비교처럼 구매 결정을 돕는 정보
- **꽃말·스토리**: 반전 꽃말, 계절 꽃 이야기 등 "친구에게 알려주고 싶은" 상식

**구성 규칙:**

- 분량은 **5장 내외** (±2장). 캐러셀은 최대 20장까지 가능하지만 완독률이 급락한다
- **모든 카드는 단독 노출을 견뎌야 한다.** 탐색 탭·공유 화면에서는 중간 카드가
  혼자 노출될 수 있다. 각 카드에 페이지 번호와 최소한의 맥락(시리즈명)을 넣는 이유다
- **첫 1~3장은 각각 독립적인 훅(hook)**: 앞 맥락 없이도 시선을 잡아야 한다.
  훅 공식 — 질문형("이 꽃, 볼 때마다 분위기가 달라진다고?"), 반전형("예쁘기만
  한 줄 알았지"), 숫자형("선물 실패 안 하는 3가지 기준")
- **첫 장은 피드·프로필 그리드의 썸네일이다.** 그리드에서는 중앙이 크롭될 수
  있으니 핵심 비주얼과 문구를 캔버스 중앙부에 배치한다
- 카드 1장 = 핵심 메시지 1개. 정보 밀도는 시리즈 전체로 확보하고,
  개별 카드는 3초 안에 읽히게 만든다
- **마지막 장 CTA는 구체적 타깃을 지목한다.** "좋아요 부탁드려요"(뻔함) 대신
  "기념일 선물이 고민인 친구에게 이 게시물을 DM으로 공유해 보세요"(행동 유도).
  저장 유도도 명시적으로: "나중에 선물 고를 때 보게 저장해 두세요"
- 스마트스토어 유도 문구와 링크는 마지막 장에만 넣는다 (매 장 반복하면 광고 피로)

## 2. 원고 톤앤매너

- **사람 대 사람의 대화체.** 공식적인 브랜드 홍보 문구가 아니라, 꽃 전문가가
  단골손님에게 유용한 꿀팁을 속삭이듯 친근하고 솔직하게
- 이모지는 훅 카드에 0~1개 수준으로 절제. 본문 카드에는 쓰지 않는다
- 과장·최상급 표현("최고의", "무조건") 대신 구체적 사실("토양 산도에 따라
  색이 달라집니다")로 신뢰를 만든다
- **접점은 하나**: 카드의 유일한 연락 접점은 네이버 스마트스토어 링크다
  (이메일·전화번호는 넣지 않음 — 사용자 확정 정책)

## 3. 규격과 디자인 규칙

- **캔버스: 1080×1350px (4:5 세로형)** — 모바일 화면 점유율을 극대화하는
  현행 권장 규격. 렌더는 2배율로 해서 최종 2160×2700px을 만든다
- **안전 여백**: 상하좌우 최소 80px 안쪽에만 텍스트·핵심 요소 배치.
  모든 요소는 이 여백 안에 들어오고 서로 겹치지 않는다
- **타이포 최소 크기(1080px 기준)**: 헤드라인 48px 이상, 본문 20px 이상,
  라벨·캡션 12px 이상. 폰에서 엄지 스크롤 중에 읽히는 하한선이다.
  단, 작은 화면에서 실제로 시원하게 읽히려면 이 하한선만으로는 부족하다 —
  아래 "4. 모바일 가독성" 규칙을 함께 적용할 것
- **시리즈에 하나의 '숨은 색 스토리'를 심는다**: 예 — 수국 편에서는 카드
  1→5의 배경·잉크 색을 청보라→라벤더→로즈핑크로 서서히 이동시켜, 수국이
  토양 pH에 따라 변색하는 원리를 설명하기 전에 색으로 먼저 느끼게 했다.
  이런 은은한 장치가 "만든 사람이 공들였다"는 인상과 재열람을 만든다
- **일러스트 정책**: 웹에서 가져온 사진 사용 금지(저작권). 코드로 그린
  SVG 라인아트(파이썬으로 좌표 계산), 또는 사용자가 직접 제공한 제품 사진만 사용
- 기본 비주얼 시스템은 `references/design-system.md`의 "Suspended Herbarium"
  (표본 도감 스타일)을 따른다. 새 캠페인에서 다른 무드가 필요하면 새 디자인
  철학을 정의하되, 브랜드 상수(팔레트 계열, 절제된 타이포)는 유지한다

## 4. 모바일 가독성 (작은 화면에서 시원시원하게 읽히기)

인스타그램 피드·탐색 탭에서 카드뉴스는 실제로 손바닥보다 작은 크기
(폭 350~400px 남짓)로 먼저 노출된다. 풀사이즈로 열어봤을 때 근사해 보여도,
축소된 상태에서 글자가 뭉개지거나 여백이 답답하면 스크롤 중 그냥 넘겨진다.
"시원시원하게 보인다"는 인상은 디자인 단계가 아니라 **축소된 상태에서** 결정된다.
아래 규칙은 3장의 최소 크기 규칙보다 한 단계 더 엄격하다 — 겹치지 않고
공존하니 둘 다 지킨다.

- **글자 크기는 여유 있게**: 헤드라인 56px 이상, 섹션 제목 38px 이상,
  꼭 읽혀야 하는 본문(꽃말·CTA 문구) 22px 이상. 장식용 캡션·카탈로그 번호만
  12~14px을 허용한다
- **의미 전달용 텍스트는 굵게**: Light/Thin 굵기는 카탈로그 번호 같은 장식
  라벨에만 쓴다. 헤드라인·CTA·핵심 정보처럼 반드시 읽혀야 하는 텍스트는
  Regular 이상, 되도록 Medium~Bold를 쓴다. 얇은 세리프는 확대 화면에선
  우아해 보여도 축소하면 실선처럼 흐려져서 안 읽힌다
- **대비를 확실하게**: 장식 라벨은 opacity 0.5~0.75도 괜찮지만, 꼭 읽어야
  하는 텍스트는 opacity 0.85 이상으로 올린다. 옅은 잉크색 + 옅은 배경 조합은
  랩탑 화면에선 멋스러워 보여도 폰을 야외에서 볼 때는 잘 안 보인다
- **줄바꿈은 짧게**: 헤드라인 한 줄은 한글 기준 14자 내외로 끊는다. 너무
  길면 좁은 화면에서 답답해 보이거나 폰트가 강제로 눌린 것처럼 보인다.
  한 문장에는 정보 하나만 — 쉼표로 여러 사실을 이어붙이지 않는다
- **축소 검수는 선택이 아니라 필수**: 렌더가 끝나면
  `python3 scripts/thumbnail_check.py <output폴더>`로 각 카드를 실제
  피드 썸네일 크기(폭 360px)로 줄인 미리보기를 만든다. 그 축소본을
  **Read 도구로 직접 열어서** 원본이 아니라 축소본 기준으로 가독성을
  판단한다 — 풀사이즈에서는 멀쩡해 보여도 축소하면 흐려지는 텍스트가
  실제 사용자가 겪을 실패 지점이다

## 5. 제작 파이프라인

```
작업폴더/
├── html/           # card1.html ~ card5.html + base.css
│   └── icons/      # SVG 일러스트
└── output/         # 렌더 결과 PNG + PDF
    └── thumbnails/ # 가독성 검수용 축소본 (360px 폭)
```

1. `assets/base.css`를 작업폴더 `html/`에 복사해서 시작점으로 쓴다
   (표본 프레임, 격자 배경, 상하단 바 등 공통 컴포넌트 포함)
2. 카드별 HTML 작성. 한글 폰트는 시스템의 Noto Serif/Sans CJK KR을 쓴다.
   렌더 전에 `fc-list | grep -i "CJK KR"`로 설치 여부를 확인하고 없으면
   `apt-get install fonts-noto-cjk`
3. 렌더: `node scripts/render.js <html폴더> <output폴더>`
   (playwright가 전역 설치된 환경에서는 `NODE_PATH`에 전역 node_modules 경로 지정)
4. 가독성 검수용 축소본 생성: `python3 scripts/thumbnail_check.py <output폴더>`
   (Pillow 필요 시 `pip install pillow --break-system-packages`)
5. PDF 번들이 필요하면: `pip install img2pdf --break-system-packages` 후
   `python3 -c "import img2pdf,glob; open('output/cards.pdf','wb').write(img2pdf.convert(sorted(glob.glob('output/card*.png'))))"`

## 6. 검수 체크리스트 (렌더 후 반드시)

렌더된 PNG를 **Read 도구로 직접 열어서 눈으로** 확인한다. HTML 코드만 보고
통과시키지 말 것 — 실제로 첫 렌더에서는 여백 쏠림·텍스트 겹침이 자주 발견된다.

- [ ] 텍스트 잘림·겹침 없음, 모든 요소가 프레임 안에 있음
- [ ] 여백 균형: 위아래 어느 한쪽에 공백이 쏠려 있지 않은가 (flex 중앙 정렬 활용)
- [ ] 색 대비: 밝은 배경 위 옅은 글자가 폰에서 읽히는 수준인가
- [ ] **360px 축소 미리보기**(`thumbnails/`)에서도 헤드라인과 CTA가
      또렷이 읽히는가 — 원본만 보고 통과시키지 말 것
- [ ] 맞춤법과 브랜드 정보 정확성 (특히 스토어 주소 `smartstore.naver.com/itecha`)
- [ ] 페이지 번호(01/05 형식)와 시리즈명이 매 장에 있는가
- [ ] 첫 장만 따로 봤을 때 넘겨보고 싶은가 (훅 강도)
- [ ] 마지막 장에 저장/DM 공유 유도 + 스토어 링크가 있는가

문제를 발견하면 새 요소를 추가하기보다 **기존 요소를 다듬어서** 해결한다.
(더 정교하게, 더 절제되게 — 장식을 늘리는 방향은 대부분 퇴보다)

## 7. 전달과 기록

- 개별 PNG(인스타 업로드용)와 통합 PDF(시안 검토용)를 SendUserFile로 전달
- 진행 상황·미완료 항목을 프로젝트 문서(`claude/canva-card-news-progress.md`)에
  갱신해서 다음 세션이 이어받을 수 있게 한다

- 구매 혜택(현재): 쇼핑백 + 메시지카드 + 액세서리 풀 패키지 무료 증정
- 주 타깃: 기념일 선물을 찾는 20~40대, 부모님 선물 수요(5060 수신자)

## 번들 리소스

- `scripts/render.js` — html 폴더의 card*.html을 일괄 PNG 렌더 (Playwright, 2배율)
- `scripts/thumbnail_check.py` — 렌더된 PNG를 피드 썸네일 크기(360px 폭)로 줄여
  `output/thumbnails/`에 저장 (가독성 검수용, 4장 참고)
- `assets/base.css` — Suspended Herbarium 공통 스타일 시작점
- `references/design-system.md` — 기본 디자인 시스템 상세 (팔레트, 폰트, 레이아웃 스펙).
  디자인 단계에 들어가기 전에 읽을 것
