# 테차 매거진 — 발행이 왜 이렇게 도는가 (근거 문서)

> **정본은 `.claude/skills/techa-publish/SKILL.md`** 다. 초안 작성은 `docs/routine-draft.md`,
> 분량·구조 규격은 `docs/channel-specs.md`. 이 문서는 **스크립트가 무엇을 왜 하는지**를
> 남기는 근거 문서다 — 규칙이 바뀌면 SKILL.md·스크립트와 함께 여기도 고친다.
> 폐기된 규칙의 경위는 `docs/archive/blog-seo-history.md`.

## 목적

테차 매거진은 광고 수익이 아니라 **테차(프리저브드 플라워) 브랜드의 검색 노출**을 키우는
보조 자산이다. 글은 순수 검색 의도 충족과 브랜드 신뢰를 기준으로 쓴다.

## 구조 원칙 (왜 게시판이 아닌가)

- DB·로그인 없는 정적 사이트. 글 하나 = 정적 HTML 파일 하나 (`/blog/<slug>/index.html`).
  빌드 과정이 없다 (`build-principles.md`).
- **글 목록(`/blog/index.html`)과 홈(`index.html`)의 글 링크는 HTML 소스에 직접 쓴다.
  JS 로 생성하지 않는다.** 네이버 크롤러(Yeti)는 JS 가 런타임에 만든 `<a>` 를 못 볼 수
  있다. (2026-07-28 이전엔 `site.js` 의 `POSTS` 배열 + JS 렌더링이었다 — 이 이유로 버렸다.)
- `index.html` 은 대시보드형 구조(사이드바 + 검색바 + 히어로 + 통계칩 + 매거진 카루셀 +
  도구 테이블 + 오른쪽 위젯). 글 링크가 나오는 곳은 **캐러셀(최신 3개 상한)** 과
  **오른쪽 "테차 매거진" 위젯(최신 5개 상한)** 두 군데다. 이 상한 관리와
  `transition-delay` 재부여를 손으로 하다 빠뜨리기 쉬워서 `publish-draft.js` 가 맡는다.

## 스크립트가 하는 일

초안은 저장소 밖 스크래치 폴더에 만들고(`routine-draft.md`), 발행 때 매거진 최종본만
`docs/drafts/<날짜>-<slug>.md` 로 들여온다. 스크립트는 그 파일을 읽는다.

| 스크립트 | 무엇을 |
|---|---|
| `scripts/publish-draft.js` | 초안 → 발행본 HTML + `blog/index.html` 카드 + `index.html` 캐러셀/위젯(상한·delay 처리) + `sitemap.xml`. 멱등(재실행 시 갈아끼움) |
| `scripts/prepare-images.js` | 이미지 슬롯 채우기 — `--from <스크래치폴더>` 에서 읽어 3:2 크롭·워터마크 제거·용량 압축해 `blog/<slug>/` 에. AI 컷은 우하단 워터마크 크롭이 기본, `--photo` 면 촬영본으로 보고 가운데 크롭 |
| `scripts/check-publish.sh` | 발행 게이트 — 발행본·목록·메인·사이트맵·내부링크·분량(`channel-specs.md` 기준)·이력을 기계적으로 확인. ❌ 있으면 커밋 금지 |

## 이미지 규칙

실물 촬영본이 있으면 항상 우선. 없으면 힉스필드/나노바나나 생성 → 우하단 워터마크를 잘라낸다.

1. **프롬프트에서 우하단을 여백으로 비우게 지시**: "keep the bottom-right corner as simple,
   uncluttered background". 사람이 안 나와야 하면 "no people" 도.
2. 기본 프롬프트: `Photorealistic`, 따뜻한 자연광, `no text, no watermark, no logos`.
3. **크롭**: 사이트 표준 비율 3:2, 1200px. `prepare-images.js --from <폴더>` 가 처리한다
   (수동이면 `ffmpeg -i in.png -vf "crop=w:h:0:0,scale=1200:-2" -q:v 4 out.jpg`).
   크롭 후 워터마크가 완전히 사라졌는지 미리보기로 확인 — 안 지워졌으면 크롭 폭을 줄여 재시도.
4. **원본 PNG 는 git 에 올리지 않는다** (워터마크 포함 + 용량 큼).
5. 개수보다 품질. 네이버가 공식적으로 말한 이미지 최적화는 **파일명·캡션을 본문과 연관되게
   짓고 크고 선명한 파일을 쓰는 것**이다. 대표 이미지 1장은 필수(없으면 SNS 공유 미리보기가
   `og-default.png` 로만 나감), 본문 2~3장 권장.

## 이중 발행 원칙 (techa.kr 매거진 + 네이버 블로그)

둘 다 내되 **절대 그대로 복사하지 않는다.** 매거진 `magazine.md` 는 발행되어 저장소에
남고, 네이버용 `blog.md` 는 스크래치 폴더에서 쓴 뒤 사람이 네이버에 붙여넣고 폴더째
삭제한다 — **저장소에는 안 들어간다** (2026-09-07 변경).

- **왜 둘 다**: 네이버는 자사 블로그를 VIEW 탭에서 우대하고, techa.kr 은 완전히 소유한
  자산이라 알고리즘 변화와 무관하게 장기 SEO·브랜드 신뢰가 쌓인다.
- **왜 복사 금지**: 동일 글은 중복 콘텐츠로 잡혀 한쪽만 색인되거나 순위가 갈린다.
- **순서**: `magazine.md` 를 캐노니컬로 발행 → `blog.md` 는 **문체·형식·분량을 바꿔 재구성**
  (매거진=정보형이면 네이버=경험형 1인칭). 다루는 범위는 같게. 규격은 `channel-specs.md`.
- ⚠️ **화자는 둘 다 테차(꽃집 운영자) 자신이다** (`script-guide.md` §5-3 정본).
  손님인 척 후기를 쓰면 가짜 후기라 금지. 겪지 않은 손님 에피소드를 지어내지 않는다.
- ⛔ **네이버 본문에 techa.kr 링크백 금지** (2026-08-07~). 브랜드명 "테차"만 언급.
  경위는 `docs/archive/blog-seo-history.md` §3.

## 사실 확인 수준을 밝힐 것

일반 상식 수준(화훼 관리법 등)이면 웹 교차검증 없이 쓰되, 발행 전 "일반 상식 기반, 별도
출처 검증 안 함"을 함께 알린다. 브랜드 실적·통계는 검증된 값만, 검증 여부도 밝힌다.

## 네이버 서치어드바이저 최초 설정 (한 번만)

searchadvisor.naver.com → 사이트 등록 → 소유 확인(HTML 파일/메타태그) → 사이트맵 제출
(`https://www.techa.kr/sitemap.xml`). 구글은 `index.html` 의 `google-site-verification`
메타태그로 인증 완료.

## 글감 우선순위

1. 프리저브드 플라워 관리법·활용법·선물 이야기 — 테차 본업과 직결
2. 테차 브랜드/도구 소식 (신제품, 사이트 업데이트)
3. 도구 활용 팁 (테차 서랍 계산기/추첨기와 연결되는 생활 정보성 글)
