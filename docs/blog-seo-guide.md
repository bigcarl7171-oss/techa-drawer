# 테차 매거진 — 발행 & SEO 체크리스트

**목표 변경 (2026-07-28)**: 애드센스 신청은 보류. 테차 매거진은 광고 수익이 아니라
**테차(프리저브드 플라워) 브랜드의 보조 사이트**로 검색 노출을 키우는 게 목적. 따라서
"애드센스 승인 기준"이 아니라 순수 검색 노출/브랜드 신뢰를 기준으로 글을 쓴다.

## 구조 원칙 (왜 게시판이 아닌가)
- DB·로그인 있는 게시판 없음. 글 하나 = 정적 HTML 파일 하나 (`/blog/<slug>/index.html`).
  사이트 전체가 빌드 과정 없는 정적 HTML이라 (`build-principles.md`), 이 원칙을 그대로 따른다.
- **글 목록(`/blog/index.html`)과 홈페이지(`index.html`)에 들어가는 글 링크는 반드시
  HTML 소스에 직접 작성한다. JS로 생성하지 않는다.**
  → 네이버 크롤러(Yeti)는 구글봇보다 JS 렌더링을 신뢰할 수 없게 처리한다. JS가
  런타임에 만들어내는 `<a>` 링크는 네이버가 아예 못 볼 수 있음. (2026-07-28 이전에는
  `site.js`의 `POSTS` 배열 + JS 렌더링 방식이었으나, 이 문제 때문에 정적 HTML 방식으로
  변경함 — `renderMagazineTeaser`/`renderMagazineList`/`POSTS` 삭제됨.)
- **2026-07-29 랜딩페이지 리디자인**: `index.html`이 대시보드형 구조(사이드바 + 상단
  검색바 + 히어로 + 통계칩 + 매거진 카루셀 + 도구 테이블 + 오른쪽 위젯)로 바뀌면서,
  `#magazine-teaser`는 더 이상 존재하지 않는다. 홈페이지에서 글 링크가 나오는 곳은
  두 군데다 — 아래 "새 글 발행 절차" 3번 참고. 스타일은 `assets/css/landing.css`
  (이 페이지 전용, 다른 페이지에 영향 없음)에 있다.

## 발행 전 확인 (필수)
글 파일을 만들었다고 바로 commit/push하지 않는다. **초안(본문 + 이미지)을 먼저 보여주고,
사용자가 확인·수정을 마친 뒤에만** commit → push로 넘어간다. 이미지가 아직 없어도 본문
초안 단계에서 먼저 검토받는다.

## 사실 확인 수준을 밝힐 것
본문 내용이 통계·수치·인용이 아니라 **일반적으로 널리 알려진 상식**(예: 화훼 관리법)
수준이면, 별도로 웹 검색을 통한 교차검증은 하지 않는다 — 다만 이 경우 사용자에게
"일반 상식 기반으로 썼고 별도 출처 검증은 안 했다"는 점을 발행 전 확인 때 함께 알린다.
브랜드 실적·통계처럼 구체적 수치를 쓸 때는 `techa-brand-rules.md`/`script-guide.md`처럼
검증된 값만 쓰고, 검증 여부를 마찬가지로 밝힌다.

## 이미지 생성 (나노바나나 + 워터마크 크롭)
실물 촬영 대신 나노바나나(Gemini 이미지 생성)로 만든다. 나노바나나 이미지는 **우측 하단에
워터마크(반짝이 아이콘)가 고정으로 들어가므로**, 아래 순서로 처리한다.

1. **프롬프트 단계에서 우측 하단을 여백으로 비워두게 지시** — 예: "Compose the main subject
   in the left two-thirds of the frame; keep the bottom-right corner as simple, uncluttered
   background for cropping." 사람 얼굴이 필요 없는 장면은 "no people"도 함께 명시.
   피사체가 정사각형에 가깝게 꽉 차는 구도(예: 협탁 위 무드등처럼 상품이 큰 경우)는
   여백 지시만으로 부족할 수 있어 크롭 시 넉넉하게 자른다 (아래 3번 참고).
2. 브랜드 실사 톤 유지: "Photorealistic", 따뜻한 자연광, no text, no watermark, no logos를
   기본으로 프롬프트에 포함 (워터마크 자체는 어차피 남지만, 다른 텍스트/로고 생성은 방지).
3. **ffmpeg로 워터마크 영역 크롭** (한 번에 안 지워지면 크롭 범위를 넓혀 재시도):
   ```bash
   ffmpeg -y -i "원본.png" -vf "crop=<w>:<h>:0:0,scale=1200:-2" -q:v 4 결과.jpg
   ```
   - 사이트 표준 이미지 비율은 3:2 (예: 2816×1536 원본 → `crop=2304:1536:0:0`으로
     우측을 잘라 정확히 3:2를 만듦).
   - 원본이 정사각형에 가까워 3:2로 자르면 상품이 잘리는 경우, 비율을 억지로 맞추지
     말고 **위쪽만 유지하는 크롭**으로 워터마크만 제거하고, `<img>`의 `width`/`height`
     속성은 실제 크롭 후 비율에 맞게 조정한다 (예: `crop=1950:1700:0:0` 후
     `width="1100" height="968"`).
   - 크롭 후 반드시 스크린샷/미리보기로 워터마크가 완전히 사라졌는지 확인 — 한 번에
     안 지워지면 크롭 폭·높이를 더 줄여 재시도한다.
   - 결과 파일은 jpg로 저장(용량 절감, 보통 원본 5~7.5MB → 100~150KB). **원본 PNG는
     git에 올리지 않고 로컬에만 보관** (워터마크 포함 + 용량 큼 + 어차피 사이트에서
     참조 안 함).
4. **이미지 개수**: 대표 이미지 1장은 필수. 글이 섹션 2~3개 이상이면 **2~3장**을 권장
   (중간에 실천/행동 장면 사진 하나, 마무리에 브랜드 연결 사진 하나 정도).

## 새 글 발행 절차

> `blog/index.html`뿐이고 글당 299자다 — 100편이어도 3.2만 자라 감당된다.
> **절대 하지 말 것: 중복 주제를 확인한다고 `blog/` 하위 글을 전부 읽기.** 그건
> `techa-cardnews/topic-pool.md`의 "이미 다룬 주제" 표가 담당한다.

1. `docs/blog-post-template.html`을 복사해 `/blog/<slug>/index.html`로 저장하고 `{{ }}` 채우기
   - slug: 영문 소문자 + 하이픈, 제목이 유추되게 (예: `preserved-flower-care`)
   - 본문 최소 500자, 실제 정보/경험 위주로 (짧고 성의없는 글은 순위에 불리)
   - **대표 이미지**: 위 "이미지 생성" 절차대로 만들어 `/blog/<slug>/cover.jpg`로 저장.
     `alt` 텍스트에 핵심 키워드를 자연스럽게 포함 (이미지 검색 유입 + 체류시간에 도움,
     텍스트 순위엔 간접적 영향). 사진이 아직 없으면 이미지 태그를 비워두지 말고,
     준비되는 대로 채울 것 — 대표 이미지 없이 발행하면 SNS 공유 미리보기도 기본
     `og-default.png`로만 노출됨.
2. `/blog/index.html`의 `#magazine-grid` 안에서 `<div class="magazine-empty">...` 플레이스홀더를
   지우고, 대신 `<div class="grid post-grid">`로 감싼 카드를 추가 (최신 글이 위로):
   ```html
   <div class="grid post-grid">
     <a class="app-card post-card" href="/blog/<slug>/">
       <div class="emoji">🌸</div>
       <div class="name">{{글 제목}}</div>
       <div class="desc">{{한 줄 요약}}</div>
       <div class="post-date">{{YYYY-MM-DD}}</div>
     </a>
   </div>
   ```
   (플레이스홀더를 `.grid` 안에 넣지 말 것 — 카드 1개만 있을 때 그리드 트랙 폭에 눌려 좁게 보임.)
3. `index.html`에는 글 링크가 **두 군데** 있다. 둘 다 최신 글이 맨 위(맨 왼쪽)에 오도록 갱신한다:
   - `.shell-carousel` 안 (테차 매거진 섹션) — 카드 형태, 커버 이미지 필요. **3열 고정 그리드**라 항상
     **최신순 3개까지만** 유지하고, 4번째로 밀려나는 가장 오래된 카드는 지운다 (4개 이상 두면
     그리드가 한 줄 넘어가며 어색하게 깨짐):
     ```html
     <a class="shell-mag-card" href="/blog/<slug>/">
       <img src="/blog/<slug>/cover.jpg" alt="{{이미지 설명}}" loading="lazy">
       <span class="shell-mag-tag">🌸 {{태그}}</span>
       <div class="shell-mag-body">
         <div class="shell-mag-title">{{글 제목}}</div>
         <div class="shell-mag-byline"><span class="shell-mag-avatar">🌿</span> 테차 매거진</div>
       </div>
     </a>
     ```
   - `.shell-right`의 "테차 매거진" 위젯 안 (`.shell-widget-head` 다음) — 목록 행 형태, 이미지 불필요.
     **최신순 최대 5개**까지만 유지하고, 6번째로 밀려나는 가장 오래된 행은 지운다:
     ```html
     <a class="shell-mag-row" href="/blog/<slug>/">
       <span class="shell-mag-row-icon">🌸</span>
       <div><div class="shell-mag-row-title">{{글 제목(짧게)}}</div><div class="shell-mag-row-date">{{YYYY-MM-DD}}</div></div>
     </a>
     ```
4. `sitemap.xml`에 새 URL 한 줄 추가 (`<url><loc>https://www.techa.kr/blog/<slug>/</loc>...`)
5. **구글**: Search Console → URL 검사 → 색인 생성 요청 (자동 크롤링을 기다리지 않고 직접 요청하면 반영이 빠름)
6. **네이버**: 서치어드바이저(searchadvisor.naver.com) → 요청 → 웹 페이지 수집 요청으로
   새 URL 제출. (사이트 최초 등록이 안 되어 있으면 아래 "최초 설정"부터.)
7. 내용과 관련된 기존 도구 페이지(예: 탄생화 계산기, 사이트 소개)에서 새 글로 가는
   내부링크를 최소 1개 추가 — 내부링크가 늘수록 두 검색엔진 모두 발견·평가가 빨라짐
8. **네이버 블로그에도 재구성해서 발행** (있는 경우) — 아래 "이중 발행 원칙" 참고

## 이중 발행 원칙 (techa.kr 매거진 + 네이버 블로그)

**결론: 둘 다 발행하되, 절대 그대로 복사하지 않는다.**

- **왜 둘 다인가**: 네이버는 자사 블로그를 검색(VIEW 탭)에서 우대하는 경향이 있어 노출에 유리하고,
  techa.kr은 완전히 소유한 자산이라 알고리즘 변화와 무관하게 장기적으로 브랜드 신뢰·SEO가 쌓인다.
  하나만 하면 한쪽 기회를 놓친다.
- **왜 그대로 복사하면 안 되는가**: 완전히 동일한 글은 검색엔진이 중복 콘텐츠로 인식해 한쪽만
  색인하거나 순위가 갈릴 수 있다.
- **순서**:
  1. techa.kr을 원본(캐노니컬)으로 삼아 먼저 발행 (위 1~7단계)
  2. 네이버 블로그에는 **다른 각도·다른 문체로 재구성**해서 작성 — 같은 문장을
     그대로 옮기지 않는다. 매거진이 정보형이면 블로그는 **후기형(1인칭 경험담)**으로 간다.
     분량은 **1,500~2,000자**, 소제목 2~3개 + 리스트 최소 1곳, 이미지 3장 이상.
  3. ⛔ **본문에 techa.kr 링크를 걸지 않는다** — 아래 방침 변경 참고
  4. 이렇게 하면 네이버 자체 검색 노출과 브랜드 인지를 동시에 얻는다

## 글감 우선순위
1. 시들지 않는 꽃(프리저브드 플라워) 관리법·활용법·선물 이야기 — 테차 본업과 직결
2. 테차 브랜드/도구 관련 소식 (신제품, 사이트 업데이트 등)
3. 도구 활용 팁 (테차 서랍의 계산기/추첨기 등과 연결되는 생활 정보성 글)
