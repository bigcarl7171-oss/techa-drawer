# 04:00 초안 루틴 지침 (2026-09-03~)

클라우드 루틴이 매일 04:00 KST에 이 문서를 따른다.
**루틴 프롬프트는 이 파일을 가리키기만 한다** — 절차가 바뀌면 여기만 고친다.

## S0 — 주문 확인 (가장 먼저)

1. `git pull`
2. `docs/drafts/NEXT.md` 의 frontmatter `slug` 를 본다.
3. **`slug` 가 비어 있으면 아무것도 하지 않고 종료한다.** "오늘은 주문이 없다"만 보고한다.
   초안을 지어내지 않는다. 이게 2026-09-03 변경의 핵심이다 — 예전처럼 topic-pool 에서
   임의로 뽑아 쓰지 않는다.

## S1 — 주문서 읽기

`NEXT.md` 에서 받는 값:

| 키 | 뜻 |
|---|---|
| `slug` | 발행 슬러그. 초안 파일명은 `docs/drafts/<날짜>-<slug>.md` |
| `topic_no` | topic-pool 번호. `none` 이면 풀 밖의 새 주제다 |
| `title_hint` | 사람이 준 제목 방향. 그대로 쓰지 않아도 되지만 뜻은 지킨다 |
| `angle` | 각도 한 줄. 이걸 벗어나지 않는다 |
| `refs` | 레퍼런스 사진 폴더 (`docs/drafts/refs/<slug>/`) |
| 본문 메모 | "넣을 것 / 피할 것". **피할 것은 반드시 지킨다** |

## S2 — 중복 검사 (사람이 정했어도 건너뛰지 않는다)

`techa-cardnews/topic-pool.md` 의 **"이미 다룬 주제" 표**와 대조한다.

- `topic_no` 가 있으면 번호표의 `사용함` 열도 함께 본다.
- 이미 다룬 주제와 **핵심 논리가 겹치면** 초안을 쓰지 말고 그 사실을 보고한다.
  (전례: `summer-flower-gift-check` ↔ `summer-fresh-flower-care` 가 겹쳐 상호 내부링크로 수습했다)
- 폐기 표시된 번호는 쓰지 않는다.

## S3 — 사진 먼저 보고 원고를 쓴다

`docs/drafts/refs/<slug>/` 의 사진을 **실제로 열어 보고** 쓴다. 순서가 예전과 반대다 —
예전엔 원고를 쓰고 프롬프트로 사진을 만들었지만, 이제는 **사진이 먼저 있고 원고가 거기 맞춘다.**

- 사진 중 원고에 쓸 3~4장을 고른다(대표 1 + 본문 2~3). 남는 사진은 그냥 두면 된다.
- 이미지 마커에 **`ref:` 로 파일명을 적는다.** 이게 있어야 발행 단계가 그 사진을 쓴다:
  ```
  [이미지 자리 1: 설명 — alt: 대체텍스트 — ref: 04.jpg]
  대표 이미지는 `## 대표 이미지 ref` 절에 파일명만 적는다.
  ```
- 사진에 **없는 것을 묘사하지 않는다.** alt 는 실제로 찍힌 것만 쓴다.
- 사진에 한글 자막·워터마크가 박혀 있으면 그 컷은 쓰지 않는다.
- 고를 사진이 모자라면 부족한 슬롯만 영문 `prompt:` 를 넣어 생성 대상으로 남긴다.

## S4 — 원고 작성

기존 규칙 그대로다. `techa-brand-rules.md` §2 품질게이트와 표현 규칙을 전부 적용한다.

- 본문 분량은 **`node scripts/publish-draft.js <slug> --dry-run` 이 세는 기준**으로 1,800~2,800자.
  루틴이 자체적으로 센 숫자는 이 기준과 다르다 — 프론트매터 `char_count` 는 참고값일 뿐이다.
- `status: draft` 로 쓴다. 사람이 검토하고 `ready` 로 바꾼다.

## S5 — 마무리

1. 초안을 `docs/drafts/<날짜>-<slug>.md` 로 커밋한다.
2. `docs/drafts/INDEX.md` 에 한 줄 추가한다.
3. **`NEXT.md` 를 `docs/drafts/orders/<날짜>-<slug>.md` 로 옮기고, `NEXT.md` 는 빈 템플릿으로 되돌린다.**
   이걸 빠뜨리면 다음 날 같은 주문으로 또 쓴다.
4. push 한다.

## 하지 않는 것

- ⛔ 주문이 없는데 주제를 지어내는 것
- ⛔ `angle` 이나 "피할 것" 메모를 무시하는 것
- ⛔ `refs/` 사진을 보지 않고 프롬프트만으로 이미지 자리를 채우는 것 (사진이 있는데도)
- ⛔ 발행까지 진행하는 것 — 발행은 9·10·11시 루틴의 몫이고, `status: ready` 는 사람만 바꾼다
