# 테차 원고 작성

**목표: 사용자 왕복 3번 안에 발행까지 간다.** 물어보기 전에 `docs/content-channel-presets.md`를
먼저 읽는다 — 화자·분량·제목 규칙은 거기 다 있고, 그걸 대화로 물어보는 게 이 스킬이
없애려는 문제다.

## 진행 순서

### 1단계 — 주제 추천 (주제를 이미 받았으면 건너뛴다)

프리셋 문서의 "주제 추천의 근거"대로 후보 3개를 뽑아 **표 하나로** 제시한다.

| # | 주제 | 왜 지금 | 노릴 키워드 |
|---|---|---|---|

그리고 "번호만 알려줘"로 끝낸다. 설명을 길게 붙이지 않는다.

### 2단계 — 초안 (한 번에 전부 낸다)

번호를 받으면 **다음을 한 메시지에 같이** 낸다. 나눠서 내면 왕복이 늘어난다.

1. **제목 3안** — 각 글자수 표기, 1순위 추천 이유 한 줄
2. **본문 전문** — 채널 프리셋의 화자·분량 그대로. 분량은 실제로 세서 숫자로 밝힌다
3. **이미지 안내** — 기존 사진 재사용이면 파일명, 새로 만들면 나노바나나 프롬프트
4. **사실 확인 수준** — 검증한 것 / 상식 기반으로 쓴 것 (`blog-seo-guide.md` 규칙)

원고는 대화에 그대로 출력한다(복붙할 수 있게). 스크래치패드에도 `.txt`로 저장해둔다.

### 3단계 — 발행

사용자가 OK하면 채널별 발행 절차를 그대로 수행한다.

- **매거진**: `blog-seo-guide.md` 1~7단계 (파일 생성 → `blog/index.html` → `index.html`
  두 군데 → `sitemap.xml` → 커밋). 커밋까지 하고, 색인 요청은 사용자가 할 일로 안내한다.
- **네이버 블로그**: 파일을 만들지 않는다. 복붙용으로 출력만 하고 끝낸다.
- 나머지 채널: 해당 가이드 문서를 따른다.

## 기본값 (물어보지 않는다)

- 채널을 안 밝히면 **매거진 + 네이버 블로그 세트**로 가정한다. 매거진을 먼저 쓴다.
- 매거진 글이 이미 있고 "블로그용"이라고만 하면 → **그 글의 네이버 재구성판**이다.
  문장을 그대로 옮기지 않는다.
- Claude ↔ 사용자 대화는 반말(`CLAUDE.md`). 원고 본문은 브랜드 톤.

## 하지 말 것

- 채널 프리셋에 이미 답이 있는 걸 되묻기 (화자·분량·톤)
- 제목만 따로, 본문만 따로 내서 왕복 늘리기
- 글자수를 세지 않고 어림잡기
- 매거진 원고를 네이버에 문장 그대로 복사
